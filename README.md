# เว็บไซต์รับสมัครงาน (Firebase Edition)

เว็บไซต์แสดงแผนก/ตำแหน่งงาน พร้อมฟอร์มสมัครงานที่:
- บันทึกใบสมัครลง **Firestore**
- อัปโหลดเรซูเม่ (PDF) ขึ้น **Firebase Storage**
- แจ้งเตือนอีเมล HR อัตโนมัติผ่าน **Firebase Extension**

ไม่ต้องเขียนเซิร์ฟเวอร์เอง ทุกอย่างทำงานผ่าน Firebase SDK ฝั่งเบราว์เซอร์โดยตรง

## โครงสร้างไฟล์

```
org-recruit-firebase/
├── index.html            โครงหน้าเว็บ + ฟอร์มสมัครงาน (หน้าสาธารณะ)
├── styles.css             ดีไซน์ทั้งหมด
├── app.js                 โหลดข้อมูลแผนกจาก Firestore, การเปลี่ยนหน้า, ส่งใบสมัคร
├── departments-data.js    ข้อมูลแผนกตั้งต้น (ใช้ seed ครั้งแรก + fallback)
├── form-defaults.js       โครงสร้างฟอร์มสมัครตั้งต้น (fallback)
├── admin.html             ★ หน้า Admin — จัดการแผนก/ตำแหน่ง + ดูใบสมัคร
├── admin.js               ตรรกะหน้า Admin (ล็อกอิน, CRUD แผนก, จัดการใบสมัคร)
├── admin.css              สไตล์เพิ่มเติมของหน้า Admin
├── firebase-config.js     ★ ไฟล์เดียวที่ต้องแก้ไข ใส่ config ของโปรเจกต์คุณ
├── firestore.rules        กฎความปลอดภัยของ Firestore
├── storage.rules          กฎความปลอดภัยของ Storage
├── firebase.json          ค่าคอนฟิกสำหรับ Firebase CLI (deploy)
└── README.md              ไฟล์นี้
```

## ขั้นตอนที่ 1 — สร้าง Firebase Project

1. ไปที่ https://console.firebase.google.com แล้วล็อกอินด้วยบัญชี Google ของบริษัท
2. กด **Add project** → ตั้งชื่อ เช่น `ssmi-recruit` → ทำตามขั้นตอนจนเสร็จ (ปิด Google Analytics ก็ได้ถ้าไม่ใช้)

## ขั้นตอนที่ 2 — สร้าง Web App แล้วเอา config มาใส่

1. ในหน้าโปรเจกต์ กดไอคอน **`</>`** (Add app → Web)
2. ตั้งชื่อแอป เช่น `recruit-site` แล้วกด **Register app**
   (ไม่ต้องติ๊ก Firebase Hosting ตอนนี้ก็ได้ ตั้งค่าทีหลังได้ในขั้นตอนที่ 8)
3. จะเห็นโค้ด `firebaseConfig = { apiKey: ..., authDomain: ..., ... }`
4. เปิดไฟล์ **`firebase-config.js`** แล้ววาง object นี้แทนค่า placeholder ทั้งหมด

## ขั้นตอนที่ 3 — เปิดใช้งาน Firestore

1. เมนูซ้าย → **Build → Firestore Database** → **Create database**
2. เลือกโหมด **Production mode** (เราจะใส่กฎเองในขั้นตอนที่ 5)
3. เลือก region ที่ใกล้ที่สุด เช่น `asia-southeast1` (สิงคโปร์) → Enable

## ขั้นตอนที่ 4 — เปิดใช้งาน Storage

1. เมนูซ้าย → **Build → Storage** → **Get started**
2. เลือก **Production mode** → เลือก region เดียวกับ Firestore → Done

## ขั้นตอนที่ 5 — ตั้งค่า Security Rules

ไฟล์ `firestore.rules` และ `storage.rules` เตรียมไว้ให้แล้ว (อนุญาตให้ทุกคนส่งใบสมัครได้
แต่ห้ามอ่าน/แก้ไข/ลบข้อมูลของคนอื่น):

**วิธีง่ายสุด — คัดลอกวางในหน้าเว็บ:**
1. Firestore Database → แท็บ **Rules** → คัดลอกเนื้อหาจาก `firestore.rules` วางแทนของเดิม → **Publish**
2. Storage → แท็บ **Rules** → คัดลอกเนื้อหาจาก `storage.rules` วางแทนของเดิม → **Publish**

**หรือถ้าถนัด CLI** ดูขั้นตอนที่ 8 ด้านล่าง (deploy พร้อมกันได้เลย)

## ขั้นตอนที่ 6 — ตั้งค่าแจ้งเตือนอีเมล HR (Trigger Email Extension)

ส่วนนี้ใช้ **Firebase Extension** สำเร็จรูปชื่อ *Trigger Email from Firestore*
ทำงานโดย: ทุกครั้งที่มีเอกสารใหม่ถูกสร้างใน collection `applications`
(ซึ่งมีฟิลด์ `to` และ `message` แนบมาด้วยอยู่แล้วจากฝั่งเว็บ) ส่วนขยายจะส่งอีเมลให้อัตโนมัติ

> ⚠️ Extension ต้องใช้แพ็กเกจ **Blaze (pay-as-you-go)** ของ Firebase แต่ยังอยู่ใน
> free tier ได้ถ้าปริมาณการใช้งานไม่เยอะ (มีบัตรเครดิตผูกไว้เฉยๆ เพื่อกันการใช้เกินฟรี)
> เมนูซ้าย → คลิกที่แพ็กเกจด้านล่าง → **Upgrade to Blaze**

1. เมนูซ้าย → **Build → Extensions** → **Explore extensions**
2. ค้นหา **"Trigger Email"** → เลือก **Trigger Email from Firestore** (ทำโดยทีม Firebase) → **Install**
3. ตั้งค่าตามนี้:
   - **SMTP connection URI**: ที่อยู่เซิร์ฟเวอร์อีเมลที่จะใช้ส่ง เช่น
     - Gmail: `smtps://YOUR_EMAIL@gmail.com:APP_PASSWORD@smtp.gmail.com:465`
       (ต้องสร้าง [App Password](https://myaccount.google.com/apppasswords) ก่อน ใช้รหัสผ่านจริงไม่ได้)
     - หรือใช้บริการส่งอีเมลโดยเฉพาะ เช่น SendGrid, Mailgun (แนะนำถ้าส่งเยอะ เพราะ Gmail มีลิมิตต่อวัน)
   - **Email documents collection**: พิมพ์ `applications`
     (สำคัญมาก — ต้องตรงกับ collection ที่เว็บเขียนข้อมูลลงไป)
   - **Default FROM address**: อีเมลที่จะแสดงเป็นผู้ส่ง
4. กด **Install extension** รอสักครู่จนสถานะเป็น Active

จากนั้นทุกใบสมัครใหม่จะทำให้มีอีเมลส่งไปหา HR โดยอัตโนมัติ

**รายชื่ออีเมลผู้รับแก้ได้จากหลังบ้าน:** เปิด `admin.html` → แท็บ **"ตั้งค่า"** →
ช่อง "อีเมลแจ้งเตือน HR" (1 บรรทัด = 1 อีเมล) → บันทึก — มีผลกับใบสมัครใหม่ทันที
ไม่ต้องแก้โค้ดหรือ deploy ใหม่ (ค่า `HR_NOTIFY_EMAILS` ใน `firebase-config.js`
เป็นเพียงค่าสำรองกรณียังไม่เคยตั้งค่าในหลังบ้าน)

## ขั้นตอนที่ 7 — ทดสอบก่อนใช้จริง

เปิด `index.html` ด้วยเบราว์เซอร์โดยตรง หรือรันเซิร์ฟเวอร์ทดสอบ (ต้อง serve ผ่าน HTTP
ไม่ใช่เปิดไฟล์ตรงๆ เพราะ ES module ต้องการ):

```bash
python3 -m http.server 8000
```

เปิด http://localhost:8000 → ลองสมัครตำแหน่งใดตำแหน่งหนึ่งดู แล้วไปเช็คที่:
- Firestore Database → collection `applications` ควรมีเอกสารใหม่ขึ้น
- Storage → โฟลเดอร์ `resumes/` ควรมีไฟล์ที่อัปโหลด
- อีเมลของ HR ควรได้รับการแจ้งเตือน (ถ้าตั้งค่า Extension เสร็จแล้ว)

## ขั้นตอนที่ 8 — Deploy จริงด้วย Firebase Hosting

```bash
npm install -g firebase-tools     # ติดตั้ง Firebase CLI (ครั้งเดียว)
firebase login                    # ล็อกอินด้วยบัญชี Google เดียวกับ Console
cd org-recruit-firebase
firebase use --add                # เลือกโปรเจกต์ที่สร้างไว้ในขั้นตอนที่ 1
firebase deploy                   # deploy ทั้ง Hosting + Firestore rules + Storage rules
```

เสร็จแล้วจะได้ลิงก์ใช้งานจริงรูปแบบ `https://YOUR_PROJECT_ID.web.app`
(ต่อโดเมนของบริษัทเองทีหลังได้ที่ Hosting → Add custom domain)

## ดูใบสมัครที่ส่งเข้ามา

ตอนนี้ยังไม่มีหน้าแอดมินในเว็บ (ตามที่ตั้งค่า security rules ไว้ว่าห้ามอ่านข้อมูลจากฝั่ง
สาธารณะ) วิธีดูใบสมัคร:
- **Firebase Console → Firestore Database → applications** เห็นข้อมูลทุกฟิลด์ กรอง/เรียงได้
- **อีเมลแจ้งเตือน** ที่ส่งไปหา HR ทุกครั้งที่มีใบสมัครใหม่

ถ้าอยากได้หน้าแอดมินในเว็บ (ต้องล็อกอินก่อนถึงจะเห็นรายชื่อผู้สมัคร) บอกได้ครับ
เพิ่มได้ทีหลังโดยใช้ Firebase Authentication + อ่านข้อมูลผ่าน Firestore rules ที่จำกัดสิทธิ์
เฉพาะอีเมลของทีม HR

## หมายเหตุด้านความปลอดภัย

- ใครก็ส่งใบสมัครได้โดยไม่ต้องล็อกอิน (ตามที่ต้องการให้เป็นฟอร์มสาธารณะ) แต่ **อ่าน/แก้ไข/ลบ
  ใบสมัครของคนอื่นไม่ได้** ตาม `firestore.rules`
- แนะนำเปิดใช้ [Firebase App Check](https://firebase.google.com/docs/app-check) เพิ่มเติม
  เพื่อกันบอท/สแปมยิงฟอร์มอัตโนมัติ (ตั้งค่าเพิ่มได้ภายหลัง ไม่จำเป็นต้องทำตอนเริ่มต้น)
- ไฟล์เรซูเม่เข้าถึงได้ด้วยลิงก์ตรงเท่านั้น (เดา URL ไม่ได้ และ Storage ไม่รองรับการลิสต์ไฟล์
  แบบเปิดเผย) แต่ไม่ได้เข้ารหัสระดับที่ต้องล็อกอินถึงจะดูได้ — ถ้าข้อมูลผู้สมัครมีความอ่อนไหวสูง
  แนะนำเพิ่ม Cloud Function ตรวจสอบสิทธิ์ก่อนคืนลิงก์ในอนาคต

## หน้า Admin — จัดการแผนก/ตำแหน่ง และดูใบสมัคร (`admin.html`)

หน้า admin ใช้ **Firebase project เดียวกัน** กับหน้าเว็บสาธารณะ (config ชุดเดียวกันใน `firebase-config.js`)
ข้อมูลแผนกถูกเก็บใน Firestore collection `departments` — แก้ไขที่หน้า admin แล้วหน้าเว็บสาธารณะจะเปลี่ยนตามทันที

### สิ่งที่ทำได้ในหน้า admin
- ➕ เพิ่มแผนกใหม่ / ✏️ แก้ไขแผนก / 🗑️ ลบแผนก / ↑↓ จัดลำดับการแสดงผล
- เพิ่ม-แก้ไข-ลบ **ตำแหน่งงาน** ในแต่ละแผนก (ชื่อ, ประเภท, คำอธิบาย, ภาระหน้าที่รายข้อ)
- ดู **ใบสมัคร** ทั้งหมด เปิดไฟล์เรซูเม่ เปลี่ยนสถานะ (ใหม่ → กำลังพิจารณา → รับเข้าทำงาน ฯลฯ) และลบใบสมัคร
- ปุ่ม **"นำเข้าข้อมูลตั้งต้น"** สำหรับใช้ครั้งแรก — นำ 7 แผนกจากไฟล์ `departments-data.js` ขึ้น Firestore
- แท็บ **"ตั้งค่า"**:
  - **อีเมลแจ้งเตือน HR** — กำหนดว่าใบสมัครใหม่จะส่งอีเมลแจ้งไปหาใครบ้าง (หลายอีเมลได้)
  - **ตัวสร้างฟอร์มสมัครงาน** — เพิ่ม/ลบ/เรียงลำดับช่องกรอกในฟอร์มได้เอง
    รองรับ: ข้อความสั้น, ข้อความยาว, ตัวเลข, วันที่, ลิงก์, ตัวเลือก (dropdown),
    แนบไฟล์ PDF และ **แนบรูปภาพ** — ตั้งเป็นช่องบังคับกรอกได้รายช่อง
    (ช่อง ชื่อ/อีเมล/เบอร์โทร เป็นช่องบังคับถาวรของระบบ ลบไม่ได้)

### ขั้นตอนเปิดใช้งาน (ทำครั้งเดียว)

**A. เปิดใช้ Firebase Authentication**
1. Firebase Console → **Build → Authentication** → **Get started**
2. แท็บ **Sign-in method** → เปิดใช้ **Email/Password** → Save

**B. สร้างบัญชี admin**
1. แท็บ **Users** → **Add user**
2. ใส่อีเมล + รหัสผ่านของผู้ดูแล (สร้างได้หลายบัญชีถ้ามี admin หลายคน)

> ⚠️ **สำคัญ:** ระบบไม่มีหน้าสมัครสมาชิก — สร้างบัญชีได้จาก Firebase Console เท่านั้น
> ใครก็ตามที่ล็อกอินได้จะมีสิทธิ์ admin เต็ม ดังนั้นสร้างบัญชีให้เฉพาะคนที่ไว้ใจ

**C. อัปเดต Security Rules**
- คัดลอกเนื้อหา `firestore.rules` และ `storage.rules` เวอร์ชันใหม่ไปวางใน Console แล้วกด **Publish**
  (rules ใหม่: ทุกคนอ่านข้อมูลแผนกได้ / เฉพาะผู้ล็อกอินที่เขียนแผนก + อ่าน-แก้-ลบใบสมัครได้)

**D. ใช้งานครั้งแรก**
1. เปิด `admin.html` → ล็อกอินด้วยบัญชีที่สร้างในข้อ B
2. กด **"นำเข้าข้อมูลตั้งต้น (7 แผนก)"** เพื่อนำข้อมูลแผนกเดิมขึ้น Firestore
3. จากนั้นเพิ่ม/แก้ไข/ลบแผนกได้เลย — ไม่ต้องแตะโค้ดอีก

### หมายเหตุ
- ถ้ายังไม่มีข้อมูลใน Firestore (หรือยังไม่ได้ตั้งค่า Firebase) หน้าเว็บสาธารณะจะ fallback
  ไปใช้ข้อมูลตั้งต้นใน `departments-data.js` โดยอัตโนมัติ เว็บจึงไม่มีวันขึ้นหน้าเปล่า
- ลิงก์หน้า admin คือ `https://โดเมนของคุณ/admin.html` — ไม่มีลิงก์จากหน้าเว็บสาธารณะ
  และตั้ง `noindex` ไว้แล้ว แต่ความปลอดภัยจริงอยู่ที่การล็อกอิน + Security Rules ไม่ใช่การซ่อน URL

### โลโก้องค์กร
วางไฟล์โลโก้ชื่อ **`logo.png`** ไว้ในโฟลเดอร์เดียวกับ `index.html` (แนะนำพื้นหลังโปร่งใส สูงประมาณ 80–160px)
— ระบบจะแสดงโลโก้ที่ header อัตโนมัติ ถ้าไม่มีไฟล์จะแสดงเครื่องหมาย "SS" สีทองแทน

### ภาษา (ລາວ / English)
- หน้าเว็บเปิดเป็น **ภาษาลาว** โดยปริยาย มีปุ่ม **ລາວ / EN** ที่มุมขวาบนสำหรับสลับภาษา
  (ระบบจำภาษาที่เลือกไว้ในเครื่องของผู้ใช้)
- ข้อความของหน้าเว็บ (ปุ่ม, หัวข้อ, ฟอร์ม, ข้อความสถานะ) แปลครบทั้ง 2 ภาษาแล้วใน `app.js` (ตัวแปร `I18N`)
- **เนื้อหาแผนก/ตำแหน่ง** มาจาก Firestore ซึ่งเป็นภาษาลาว — ถ้าต้องการเวอร์ชันอังกฤษของเนื้อหาด้วย
  ให้เพิ่มฟิลด์ลงท้ายด้วย `_en` ใน document ของแผนกนั้น เช่น:
  - `name_en`, `mission_en`, `responsibilities_en` (array)

  ระบบจะใช้ฟิลด์ `_en` โดยอัตโนมัติเมื่อผู้ใช้สลับเป็น EN และถ้าแผนกไหนยังไม่มีฟิลด์ `_en`
